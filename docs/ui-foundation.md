# UI foundation protocol

Source: [Polya UI Foundation in Notion 2.5](https://app.notion.com/p/41249fda3296813a9952eab2130ef81d).

`crates/photo-gui/src/ui_foundation.rs` owns spacing (4/8/12/16/24 logical points), typography, radii, 32-point control height and the settings control column. `ui_style.rs` consumes these tokens and supplies normal, hover, active, selection and disabled egui states. Keep native egui responses, focus IDs and enabled-state handling; these components do not intercept keyboard or pointer events.

Use `SettingsSection::show` for grouped settings, `SettingsRow::show` for label + optional description + controls, and `command_row` for commands with actions. `settings::card` and `settings::row` delegate to these components for existing pages. The legacy row width argument is compatibility only: all rows use the same bounded 360-point control column. Titles and descriptions wrap in their own zone. Below 576 points of row content width, controls move below labels, fill the available width and wrap actions. Do not add fixed-width children wider than their available column. Text edits and selectors must bound their desired width to available space. Use stable `push_id` scopes for repeated rows.

The existing Afio shortcut list and Yazi Appearance, General, Quicklinks and Keybindings pages use these components. Own and effective keybinding rows use the same command-row geometry; editor labels, empty search results and persistence errors retain their existing commands and state behavior. Settings shell and application style share tokens with page controls.

For changes, run `cargo test -p photo-gui ui_foundation::tests` and existing shortcut/settings tests. Geometry fixtures cover narrow/normal/wide content widths, pixels-per-point 1/1.5/2, long Russian titles and descriptions, checkboxes, selectors, buttons, action groups, empty/error messages and click/focus responses. Check label/control separation, content bounds, column right edges and minimum heights. These headless assertions verify layout contracts; they do not establish subjective visual acceptance or physical OS input routing. Native screenshot review remains useful for rendered fonts, contrast and overall appearance.

Native verification limitation: the pinned eframe 0.36.2 Glow backend processes `Screenshot` actions in its root/deferred paint path, but does not process them in `render_immediate_viewport`. Settings uses an immediate viewport. Its API capture therefore returns explicit `InvalidState`; root frame capture remains supported. `scripts/check-ui-foundation.py` checks all 15 existing page/width states through the API, verifies that explicit result, and records the headless geometry test log. It does not produce or claim native Settings screenshots. Human visual acceptance remains outstanding.

Yazi keybinding editors belong immediately below the selected command row. New bindings open by the add button. `yazi_key_capture` consumes recording input before Settings Escape and shortcut handlers; printable text records sequential keys in the active keyboard layout, while modified key events record Yazi chords. Escape restores the previous sequence; the Done button ends recording. The manual notation field is optional and collapsed. Keep the existing `ConfigureYazi` validation and explicit conflict replacement path. Check `yazi_key_capture::tests` for input ownership and localized inline geometry, and `scripts/check-yazi-keybindings.py` for isolated native sequence/conflict contracts.
